# GitHub credential convenience

On macOS, the lead can opt in to storing the GitHub token as a generic password in their own default Keychain. `npm run setup -- --github-token` launches the system `security` command with `-w` as its final argument so the OS prompts interactively; the application never receives the typed token as an argument or prints it. `--github-token --remove` removes only that named Keychain item. Neither command touches connector credentials or the Konfab database. Require an interactive terminal for adding; reject unsupported platforms and mixed setup options with a clear message. Tests use an injected fake command, never the real Keychain.

At server startup, prefer a nonempty `KONFAB_GITHUB_TOKEN`; otherwise, on macOS, retrieve the named Keychain item through the system command with a bounded timeout and captured stdout. Do not log stdout, stderr, error objects or the token. Missing/unavailable Keychain leaves the token unavailable; if token use had been enabled, existing checks fail clearly rather than sending unauthenticated requests. Keychain may request macOS authorization. The source is reported as environment, Keychain or unavailable, never the value. Existing explicit token-use opt-in remains required before any request sends a credential. Environment precedence gives an escape hatch and supports non-macOS installations.

Document that typing secrets in shell commands can leave history, that Keychain protects at rest but is not a guarantee against code running as the same user, and that deleting a Keychain item or removing history does not revoke a leaked token. No live user's credential or Keychain item is touched during testing; test status, precedence, missing/error/timeout paths, safe arguments, and redaction with fake processes. Separately, simplify the Public Sources page and distinguish navigation tabs, with an explicit notice when a previously loaded page reconnects to a restarted server. Review the design and implementation before committing.
