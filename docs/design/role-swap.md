# Role swap

Reassign two or more room members' role assignments and room notes in one database transaction, guarded by every affected assignment revision number. A swap is the two-member case; chained swaps support rotations, and the same transaction can assign reviewed saved roles or remove roles. Support saved role packs, custom text and empty roles; retain each member's edit permission. Reject self-swaps, missing/archived members, stale previews and unavailable or unreviewed pinned revisions. Insert a system-labelled handover message and one role-change event per affected member in the same transaction, then notify listeners once. No automatic handover can know about uncommitted work: the message prompts both agents to describe it.

An active turn must finish with its original role, including custom-role instructions and role/skill file access. Snapshot its full role envelope and custom role text before the first swap affecting that turn; repeated swaps must not replace that snapshot. `wait_for_turn` replay and role/file reads during the active turn use the snapshot, and the next turn sees the latest swapped assignment. Session replacement, multiple swaps and database reopen must not leak new role details into the active turn. Other changes to permissions are outside this feature.

The current messages table permits user and agent sender types. Store the handover with the existing user storage type and a reserved system sender ID, expose it as `system` at the API boundary, and render it as System rather than as a lead message. It must not create turns or impersonate the lead. The UI previews all affected roles, notes and revision tokens before confirming; it keeps the old editor and handles a conflict without partial changes.

Test pack/pack, custom/custom, mixed and empty roles, stale and archived members, edit permissions, notes, active turn replay and role/skill reads, repeated swaps, event/message atomicity and a real database reopen. Verify the card flow in an isolated instance. Update the guide and requirements. Review this note and implementation before committing.
