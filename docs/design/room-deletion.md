# Permanent room deletion

Only an archived room can be deleted, by a signed-in lead through the local page. A preview computes current room counts and attachment-record bytes; the final request must include the exact room name, and the server rechecks archive and name at deletion time. The dialog offers the existing Markdown export and says backups, exported copies and other apps' conversations are not removed. Do not perform a real deletion as part of development or testing.

Delete database rows in a transaction in dependency order, including indirect children (decision versions; waits and warnings belonging to sessions; handoffs referencing messages or turns), converted-role history and room-member roles. Audit the schema for room IDs and foreign keys, and audit serialized bridge receipts that can retain a room's join result or session-scoped request; remove only matching receipts. Preserve shared agents, personal skills and roles, and project files. Add one global audit event with room name, counts and timestamp, no message content. The actual database and filesystem cannot share a transaction: persist a cleanup tombstone in the same database transaction as deletion, then remove only the exact numeric room directory beneath the configured attachments root. Refuse symlinked roots or room directories; do not traverse them. Retry only tombstoned IDs at startup rather than deleting all unknown folders. Retain failed tombstones and surface cleanup failure; never claim files were removed when they were not.

Run VACUUM outside the transaction, only if supported; record a retry marker on failure and retry at a safe startup point. VACUUM reclaims local SQLite free pages, not a promise of secure erasure or removal from WAL, backups, exports or external copies. UI should report separately whether room rows were deleted and whether disk cleanup is pending. Never delete arbitrary paths from a database value. Tests use disposable homes and cover invalid room/name, room-only scope, schema coverage and indirect rows, receipts, restart after cleanup interruption, failed vacuum, symlink rejection, and existing-room preservation. Review this design before commit.
